Theory

Agents that can remember information across sessions are far more useful than those starting from scratch every time. To enable this, you need persistent storage systems that can handle different types of data — structured records you want to retrieve by exact field values, and unstructured text you want to retrieve by meaning.

In this task, you will implement two complementary storage backends that together cover most real-world memory needs for AI agents.

StructuredStore

The StructuredStore uses TinyDB, a lightweight document database that persists data to a local JSON file. It is ideal for storing categorical or relational data — things like user preferences, settings, or any information you'd want to look up by a specific field value.

Initialize it with a persistent database file and a named table:

self.db = TinyDB('memory.json')
self.table = self.db.table('memories')

To query by a specific key-value pair, use TinyDB's Query() object:

User = Query()
results = self.table.search(User[key] == value)

VectorStore

The VectorStore uses ChromaDB for semantic similarity search. Rather than matching exact field values, it finds documents that are semantically related to a query — so searching "What food do I like?" can surface "I love pizza" even without any keyword overlap.

Each document is stored alongside its embedding vector, generated via the _embed() helper method (already implemented for you) using OpenAI's text-embedding-3-small model. Initialize ChromaDB with persistent storage and cosine similarity:

self.client = chromadb.PersistentClient(path="./chroma_db")
self.collection = self.client.get_or_create_collection(
    name="memories",
    metadata={"hnsw:space": "cosine"}
)

When storing, generate a unique ID with uuid.uuid4() and add the embedding and document together. When querying, embed the query string and pass it to collection.query().

Both stores should persist data across sessions — use the persistent client options for both TinyDB and ChromaDB rather than in-memory alternatives.

Description

The CLI structure and the _embed() helper are already implemented. Your task is to implement the StructuredStore and VectorStore classes — their store(), query(), and flush() methods.

The CLI exposes six commands across the two stores. Structured store commands parse input in key=value;key=value format before passing it to your class. Vector store commands pass raw text strings. Do not modify the CLI command structure.

Objectives

This is what you need to do here:

  1. Implement StructuredStore using TinyDB — initialize with a persistent JSON file, implement store() to insert dictionary data, query() to search by key-value pair with an n_results limit, and flush() to clear the table.

  2. Implement VectorStore using ChromaDB — initialize with a persistent client and cosine similarity collection, implement store() to embed and save text with a generated UUID, query() to embed the query and retrieve the top n_results similar documents, and flush() to delete all entries from the collection.

Examples

Example 1 — vector store operations:

python step2.py vector-store-add --content "I love pizza"
python step2.py vector-store-add --content "My favorite color is blue"

python step2.py vector-store-query --query "What food do I like?" --n 3
# Output: ["I love pizza", ...]

python step2.py vector-store-flush

Example 2 — structured store operations:

python step2.py structured-store-add --data "name=John;age=30;city=NYC"
python step2.py structured-store-add --data "name=Jane;age=25;city=LA"

python step2.py structured-store-query --key "city" --value "NYC" --n 5
# Output: [{"name": "John", "age": "30", "city": "NYC"}]

python step2.py structured-store-flush
