Theory

When building conversational applications, one of the most important considerations is how you manage the conversation history passed to the LLM. Every message you include costs tokens, and context windows have limits, so a naive "keep everything" approach won't scale. Instead, you need a memory management strategy that balances context retention with efficiency.

In this stage, you will implement a ConversationManager class that supports three different strategies for handling conversation history. The class is already scaffolded for you — your job is to implement the strategy functions it relies on.

Strategies

The three strategies you will implement each take a different approach to managing the message list:

The keep all strategy is the simplest — it returns the message list completely unchanged. Every message is preserved, no matter how long the conversation gets.

The sliding window strategy keeps only the most recent N messages, discarding anything older. This bounds memory usage at a fixed size regardless of conversation length:

def sliding_window_strategy(messages: list[dict], window_size: int = 10, **params) -> list[dict]:
    return messages[-window_size:]

The summarize strategy is more complicated. Once the number of messages exceeds a threshold, it takes the first half of the history and replaces those messages with a single summary message, keeping the remaining recent messages in full. To generate the summary, format the older messages into readable text (e.g. "role: content" per line) and pass them to the LLM (you can use Chat Completions or the the Responses API in this project, but choose a single one for consistent implementation). Your system prompt should instruct the model to summarize concisely while preserving key information. The summary message should follow this format:

summary = {
    "role": "system",
    "content": "Summary: " + content_summary,
    "timestamp": messages_to_summarize[0]["timestamp"]
}
return [summary] + remaining_messages

The OpenAI client is already initialized at the module level, so you can use it directly in your strategy functions.

ConversationManager

The ConversationManager class ties everything together. Each time add_message() is called, it appends the new message and immediately applies the active strategy. The get_context() method returns the current (post-strategy) message list.

The class, CLI interface, and main loop are already implemented — do not modify them. The CLI is built with the Click library, which automatically passes the CLI options (--window-size, --threshold) as keyword arguments to the strategy functions via **params. Your only task is to implement the three strategy functions.

Each message dictionary includes a role, content, and timestamp field. Make sure your strategy functions preserve this structure.

Note: The code creates timestamps with datetime.now(), which returns a datetime object. Python's json module can't serialize these, so the final print(json.dumps(conversation.get_context())) in run_conversation() will raise a TypeError. To fix this, change "timestamp": datetime.now() to "timestamp": datetime.now().isoformat() so timestamps are stored as strings.

Objectives

This is what you need to do here:

  1. Implement keep_all_strategy() to return all messages unchanged.

  2. Implement sliding_window_strategy() to retain only the last window_size messages. Handle the edge case where window_size is 0.

  3. Implement summarize_strategy() to check if the message count exceeds threshold, and if so, format the first half of history into readable text, summarize it using the OpenAI client, and return the summary message followed by the remaining messages.

Examples

Example 1: Keep all strategy:

python step1.py --strategy keep_all
Hello
How are you?
END
# All messages preserved in full

Example 2: Sliding window strategy:

python step1.py --strategy sliding_window --window-size 5
# After 10 messages, only the last 5 remain

Example 3: Summarize strategy:

python step1.py --strategy summarize --threshold 20
# Once messages exceed 20, the first 10 are replaced with a summary
# Result: 1 summary message + 10 recent messages = 11 total
